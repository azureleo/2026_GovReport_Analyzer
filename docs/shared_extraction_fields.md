# 공통 업무 필드와 변환·저장 보존

2026-11-05, `codex/trace-table-contracts`.

## 적용 범위

`utils/extraction_schema.py`가 16개 업무 시트의 이름·필드·표시 별칭·수치와 단위 연결을 정의합니다.
텍스트 추출의 JSON 예시, 가이드라인의 개별 시트 지시, config의 출력 헤더, Vision 변환,
Organizer, Excel writer와 저장 대조가 같은 정의를 소비합니다. 기존 업무 열의 순서를 유지하고
추가 문맥 열을 뒤에 붙입니다. 고정된 과거 골든의 채점 계약은 변경하지 않습니다.

모델·provider·추론 강도·실제 `.env`는 변경하지 않았습니다. 추가 모델 호출이나 자동 재호출도
추가하지 않습니다. 기존 `main.py` 명령으로 적용되며 별도 ON 설정은 필요하지 않습니다.

## 공통 필드 정의

| 구분 | 정의 및 처리 |
|---|---|
| 사업·부문 | 사업명, 관리번호, 부문·세부부문을 구분. 표 제목을 사업명으로 대신 저장하지 않음 |
| 지표 | 원문에 명시된 업무 수치 필드명을 사용. 목표감축량·목표배출량·감축률·활동량·예산액을 구분 |
| 범위 | 목표범위·전망범위는 명시된 범위만 유지. 지자체명으로 추정하지 않음 |
| 재원 | 국비·시도비·도비·시비·군비·구비·시군구비·민간·기금·기타 등을 보존. 구비→도비 치환 금지 |
| 미표기 재원 | null/공란 또는 원문의 미표기 표현을 유지. 합계로 만들지 않음. 계/총계→합계만 동치 처리 |
| 단위 | 단위와 배율을 원문대로 보존. 수량·감축량·금액 단위를 서로 복사하지 않음 |
| 시간 | 연간값은 연도, 기간 합계·평년값은 연도=null 및 명시된 기간시작·기간종료 |
| 표 계층 | 행경로·열경로를 상위 머리글부터 배열로 보존. 전망의 직간접구분·상위부문도 별도 보존 가능 |
| 원문/계산 | 값출처=원문/계산/미확인. 한 행의 출처가 다르면 필드별 객체. 추정된 출처를 코드가 채우지 않음 |
| 별칭 | 내부 감축률 ↔ Excel 감축률(%). 과거 두 표기를 모두 입력으로 받고 0도 보존 |
| 별칭 충돌 | 서로 다른 두 원값을 field_contract_review에 보존. 충돌 셀만 공란으로 보류하고 검증리포트에 기록 |

수치 8개 시트에 지표종류·계획문맥·시간기준·기간시작/종료·행경로·열경로·값출처를 추가합니다.
06에 단위·세부부문, 05에 직간접구분·상위부문, 10에 감축량유형·감축원단위단위,
11에 관리번호를 보존합니다. 값이 없으면 새 열은 비어 있습니다.

## Vision 변환

시스템의 구형 5개 분류 지시를 현재 정의와 맞추고 단건·묶음에 같은 계약을 전달합니다.
본문 지원은 지역여건·지역/관리권한 배출현황·전망·감축목표·사업목록·연차별 이행·정량감축·재정의
9개입니다. 비전전략 분류는 검토 전용이며, 다른 정성 시트를 자동 지원한다고 표시하지 않습니다.
혼합 표는 각 행의 target_sheet로 나눌 수 있습니다.

- fields의 명시 사업명·재원·계획구분·세부부문·방법론·기간·단위·표 경로를 업무 행으로 옮깁니다.
- 재원을 합계로, 계획구분을 온실가스감축대책으로 고정하지 않습니다.
- fields에 명시된 수치 필드를 우선합니다. 일반 값이 어떤 지표인지 불명확하거나 다른 명시 값과
  충돌하면 자동 본문 반영을 보류합니다. 단순 ‘목표’를 목표배출량으로 간주하지 않습니다.
- 명확한 연간 감축량은 목표감축량으로 보존합니다. 사업별 정량감축은 10번 시트를 사용합니다.
- 명시한 기준배출량·기준연도는 과거 기준값으로 보존하며 목표연도를 만들지 않습니다.
- 명시한 유효 기간은 단일 연도가 없어도 보존합니다. 잘못된 기간이나 필요한 시간 정보가 없으면 보류합니다.
- 일반 단일 연도 행의 기존 허용 범위·신뢰도·참고자료·그래프 추정 제외 규칙은 유지합니다.
- 미지원 시트나 귀속 불명확 응답은 배출현황으로 자동 전환하지 않습니다.
- 같은 응답을 재사용하면 기존 엄격 병합으로 본문 중복을 줄이며, 값 충돌은 양쪽과 사유를 보존합니다.

## 저장 및 진단

감축률 별칭과 문맥 열의 저장은 FACT_CONTRACT_MODE와 독립입니다.
off·audit·enforce 모두 동일한 출력 스키마를 사용합니다. enforce는 선택적 엄격 검사·격리·병합 규칙을
추가합니다. TABLE_HEADER_PATHS_ENABLED는 별도의 입력 보강 설정입니다.

기존 `실행명_pipeline_audit.json`의 ledgers에 다음을 저장합니다. run-state OFF에도 저장됩니다.

- field_schema_version: 공통 정의 버전
- field_contract_review: 필드 별칭 충돌과 원행
- vision_analyses: 파싱에 성공한 Vision 분석 객체. 변환 전의 추가 필드 포함. 응답 문자열 자체와는 구분
- chart_observations: 원시 행·변환 후 행·정제 전 병합 허용 여부·보류 사유·객체/근거 ID
- vision_trace: 별도 원응답·행별 판정·저장 셀 대조 파일의 경로와 요약 (11월 6일 추가)

`chart_observations.반영여부=반영`은 정제 전 병합 허용입니다. 최종 Excel 저장을 뜻하지 않습니다.
문자열 원응답은 파싱 전에 별도 저장하고, 실제 셀 대조는 [Vision 기록 안내](vision_response_trace.md)의
`excel_links.jsonl`을 확인합니다. 이전 실행의 미저장 원응답을 소급 복원하지는 않습니다.

과거 Excel에 신규 선택 열이 없으면 저장 검사에서 미평가 진단으로 구분합니다. 현재 실행의
메모리 값이 실제 셀에서 사라졌는지는 저장 후 대조로 계속 확인합니다. 과거 골든 파일이나 기존
평가 결과를 소급해서 변경하지 않습니다.

## 비교 시 주의점과 검증

이번 수정은 OFF 경로의 저장 손실도 고칩니다. 과거 OFF와 새 OFF가 완전히 같은 구현이라고
간주하지 말고 커밋·구현 해시를 기록해야 합니다. 수정한 코드에서 OFF/ON을 다시 비교할 때는
같은 공통 필드 스키마를 사용하므로 계약 강화 효과와 기본 저장 지원의 차이를 구분하기 쉽습니다.

```powershell
# 환경 파일을 읽지 않는 오프라인 검증
$env:PYTHON_DOTENV_DISABLED = "1"
$testTemp = Join-Path (Get-Location) ("output\field_tests_" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $testTemp | Out-Null
$env:TEMP = $testTemp
$env:TMP = $testTemp
py -m pytest tests/test_shared_extraction_fields.py tests/test_fact_contracts.py tests/test_fact_contract_pipeline.py tests/test_main_v9_forecast_contract.py tests/test_main_v9_end_to_end.py tests/test_saved_quality.py tests/test_saved_quality_pipeline.py -q --basetemp "$testTemp\pytest"
```

모델 경계만 모의 처리하고 실제 PDF·변환·정제·병합·Excel 저장·재조회·감사 저장을 통과합니다.
검증은 연결 및 회귀 확인입니다. 새 프롬프트의 실제 모델 정확도·호출 시간 효과는 별도 실측 대상입니다.
