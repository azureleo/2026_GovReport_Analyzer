# Vision 응답·보류 기록과 판독 지시

## 적용 범위

기존 `main.py` 실행에서 이미지를 처리하면 자동 적용합니다. 새 CLI 옵션이나 `.env` 수정은 필요하지
않습니다. `--no-images` 실행에는 새 Vision 기록을 만들지 않습니다. 라이브러리에서 `ImageAgent()`만
직접 호출할 때는 파일을 만들지 않으며, 필요하면 `ImageAgent(trace=VisionTrace(output_path))`로 연결합니다.

모델·provider·추론 강도·timeout·기존 재시도 상한은 변경하지 않습니다. 기록 실패 때문에 추가 모델
호출을 하지 않습니다. 기록 실패는 경고와 실행 결과 메타데이터에 남기고 이미 저장한 Excel을 보존합니다.

## 실행별 저장 위치

`output/실행명.xlsx`를 기준으로 다음 파일이 생깁니다.

| 위치 | 내용 |
|---|---|
| `실행명_vision_trace.json` | 최신 기록 세션의 경로, 호출 상태, 행별 허용/보류 집계, 저장 연결 요약 |
| `실행명_vision_trace/세션ID/calls/호출ID.json` | 호출 전 지시문·시스템 지시·이미지 매핑, 응답 해시, 파싱 상태와 입력 진단 |
| `…/responses/호출ID.txt` | `llm_client`가 돌려준 문자열을 UTF-8로 그대로 저장. 파싱·코드블록 제거 전 |
| `…/decisions.jsonl` | 행별 원시 값·변환 값·분류 보완 근거·병합 허용/보류 이유·호출/객체/근거 ID |
| `…/excel_links.jsonl` | 실제 Excel의 시트·행·수치 대조와 정제 이후 검토/격리 사유 |
| 기존 `실행명_pipeline_audit.json`, `실행명_run_outcome.json` | `vision_trace` 요약과 상세 파일 위치 |

호출 전 요청을 기록하고, 응답은 파싱 전에 저장하며, 행별 결정은 배치마다 저장합니다. 뒤의 호출이
중단되어도 앞선 응답과 결정 파일은 남습니다. 같은 출력 이름을 다시 사용해도 세션 폴더를 새로 만들어
앞선 원응답을 덮어쓰지 않습니다. 최상위 요약은 최신 세션을 가리킵니다. run-state 설정과 독립입니다.

이미지 본문/base64와 인증정보는 저장하지 않습니다. 입력 이미지는 페이지·객체/근거 ID·좌표·캡션과
base64 문자열의 SHA-256으로 식별합니다. 실제 모델 조건은 같은 실행의 `run_manifest`와 함께 확인합니다.

여기서 원응답은 **프로젝트 LLM 클라이언트의 반환 문자열**입니다. provider의 HTTP 원문이나 클라이언트
내부 재시도 각각의 응답을 모두 기록한다는 뜻은 아닙니다. 클라이언트가 실패를 `{}`로 치환한 경우에는
정상 빈 판독으로 간주하지 않고 비정상 형태로 기록하되, 정확한 원인은 실행 로그로 추가 확인해야 합니다.
과거에 저장하지 않았던 원응답이나 미판독 값을 만들어 복원하지 않습니다.

## 상태 해석

- 호출: `requested` → `response_received` → `complete`/`partial`/`no_data`/`invalid_json`/`invalid_shape`/
  `empty_response`. 예외가 경계까지 전달되면 `transport_error` 또는 `interrupted`입니다.
- `complete`는 분석 형식 검사를 통과했다는 뜻입니다. 모든 행의 사실 정확도나 저장 성공을 뜻하지 않습니다.
- 행: `eligible`은 정제 전 병합 허용, `held`는 그 단계의 보류입니다. 모델이 명시한 `review_reasons`와
  코드의 신뢰도·기간·단위/지표·귀속 검사 사유를 함께 저장합니다. 잘못된 자료형의 원행도 남깁니다.
- 최종 셀: `excel_linked_values_equal`은 출처계보가 연결되고 제안 수치와 저장 수치가 일치한다는 뜻입니다.
  PDF 사실 정확도·단위의 정답 여부와 구분합니다. 수치 불일치나 비수치 행은 `excel_linked_review`입니다.
- 정제 뒤 실제 격리 원장에 남은 행은 `held_after_cleaning`, 연결을 찾지 못하면 `not_located_in_excel_lineage`입니다.
  후자는 곧바로 판독 오류를 뜻하지 않습니다. 상세 파일의 `post_processing_reviews`를 함께 확인합니다.
- 계보 열이 없거나 계보 JSON이 손상돼 확인할 수 없으면 `unassessed`입니다. 앞선 파이프라인 시도가
  새 시도로 대체된 경우에는 `superseded_attempt`로 구분합니다.

## 판독 및 연결 보완

1. **부문 목표와 개별 사업 구분**: 부문별 연간 감축량은 06 감축목표의 `목표감축량`에,
   식별 가능한 사업의 활동량·원단위·감축량은 10 정량감축량에 둡니다. 원문에 없는 사업명·목표범위·기준연도는 만들지 않습니다.
   저장 응답이 사업별 시트로 잘못 분류됐더라도, 명시된 부문별 감축량 제목·부문/합계·온실가스 단위가
   일치하고 사업 식별자나 다른 지표가 없을 때만 06으로 보완합니다. 신뢰도·추정값·기간 등의 기존 검사는 계속 적용합니다.
2. **세부 예산 항목**: 새 지시문은 가장 구체적인 사업명을 요청하며 상위 사업은 행경로/계획문맥에 남깁니다.
   저장 응답의 사업명이 상위 사업이고 `항목`에 세부명이 있으면 해당 명칭을 기존 `행경로` 열에 보존합니다.
   이미 명시된 경로를 덮어쓰거나 국비·시비·합계·연도를 세부사업명으로 바꾸지 않습니다.
   재정 행의 병합·사실 계약·재개 식별·품질 충돌 검사는 선택적인 행경로도 구분합니다.
3. **보조 지시 일관성**: 단건·묶음 Vision과 관련 텍스트 시트가 공통 의미 지시를 사용합니다. 단건도 같은
   페이지 문맥을 제한된 길이로 받습니다. 가이드라인은 관련 절의 완결된 문장·표 행을 선택하며,
   보조 지침은 기존 상한(최대 3개, 각 500자/합계 1,500자)을 넘지 않습니다. 불명 선택 문맥을 반복 생성할 필요는 없습니다.

## 검증

외부 모델 경계를 모의 처리하고 변환·중복/충돌 병합·Organizer·Excel 작성/재조회·Supervisor 감사 연결은
실제 코드를 통과합니다. 테스트 명령은 환경 파일을 읽지 않는 별도 PowerShell 세션에서 실행합니다.

```powershell
$env:PYTHON_DOTENV_DISABLED = "1"
$testTemp = Join-Path (Get-Location) ("output\vision_tests_" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $testTemp | Out-Null
$env:TEMP = $testTemp
$env:TMP = $testTemp
py -m pytest tests/test_vision_trace.py tests/test_shared_extraction_fields.py -q --basetemp "$testTemp\pytest"
```

연결·회귀 검증과 기존 응답 재사용 검증은 새 프롬프트의 실제 정확도·속도 검증과 다릅니다.
다음 실측에서는 기존과 같은 모델·범위·조건을 고정하고 새 응답의 행별 판독 및 최종 셀을 비교해야 합니다.
