## 결정 규칙

- **게이트 통과 → v8을 통합 기준**으로 삼고, 우리 고유 자산(프로브·D3-0
  도구·M3 문서·docs 체계)을 v8 위에 얹는다(대부분 추가형 파일).
- **게이트 미달 → 역방향**(v7+M3 기준, v8 기능을 회귀 원인 격리 후 선별
  편입) 또는 v8 측 수정 후 재측정 — 팀 논의로 선택.

## 측정 원칙

1. **채점 축은 우리(v7-5) 채점기·골든으로 고정** — v8의 채점기는 개정돼
   있어(스키마·매칭 변경) 축이 다르다. 산출물만 v8에서 받고, 채점은
   `feat/v7-extraction-fidelity`의 `scripts/score_against_golden.py`·
   `cross_backend_probe.py`·`d30_agreed_pair_accuracy.py`로 수행한다.
2. v8 실행은 v8 기본 설정 그대로(기본값 ON 기능 포함) — "통합 후 기본
   동작"을 재는 것이므로 v8 쪽을 우리 설정에 맞추지 않는다.
3. 백엔드 축 정합: 권장 구성(luna, `--agent codex`) 기준으로 비교하고,
   프로브·q는 하한 구성(gemini flash-lite) 산출물과의 쌍으로 잰다 —
   우리 기준선(v73_luna·v63f_기본, m32v1)과 동일한 쌍 구조.
4. v8 산출물의 계약 컬럼이 우리 채점기 계약과 어긋나면(신규 필드 추가
   등) 어긋남 자체를 기록하고, 채점 가능 공통 컬럼 축으로 잰다.
